## 记号约定（全片统一用这一套）

全片用 SD3 和 diffusers 的写法：**t = 1 是纯噪声，t = 0 是干净 latent**。

```
x_t = (1−t)·x_0 + t·ε          ε ~ N(0, I)
v   = dx_t/dt = ε − x_0         模型学这个速度
采样：从 t=1 往 t=0 走，x_{t−Δ} = x_t − Δ·v_θ(x_t, t)
```

各论文的原始记号方向不一样，对照见 §4。Qwen-Image 报告 Eq.(1) 的方向和这里**相反**（见 §5 冲突 1）。

## 5. 冲突与未找到

1. **Qwen-Image 报告的时间方向和代码相反。** 报告 Eq.(1)（§4.1，p15）写 `x_t = t·x_0 + (1−t)·x_1`、`v = x_0 − x_1`，t=1 是图。diffusers 的 scheduler（`:234`、`:520`）和训练脚本（`train_dreambooth_lora_qwen_image.py:1790`）都是 σ=1 为噪声、目标 `ε − x_0`。同一份报告的 RL 段 Eq.(6)–(8)（p17–18，沿用 Flow-GRPO）又换回 t=1 为噪声。片中统一用 SD3 / 2.0-RL 报告的写法，不要照抄 Qwen-Image 报告 Eq.(1)。发布权重实际输出 `ε − x_0`：推断（依据是官方 diffusers pipeline 的更新方向）。
2. **"默认分辨率"有两个答案。** README 推荐 1:1 用 1328×1328；pipeline 不传尺寸时是 1024×1024（`pipeline_qwenimage.py:177`、`:521`）。片中说"推荐 1328²（6,889 个 token）"，别说成"默认"。
3. **README 里的 4:3 尺寸不能被 16 整除。** 1472×1140 / 1140×1472 里的 1140 ÷ 16 = 71.25，pipeline 会警告并向下取整（按 `:369–370` 实际 latent 高 142 → 1136 像素）。推断，不影响 EP01。
4. **Qwen-Image 训练时的 t 分布参数和训练 shift 都没写。** 报告只说 logit-normal，没给 m、s，也没说训练时有没有按分辨率 shift。推理 shift 只能从 diffusers 配置讲。
5. **calculate_shift 的函数默认值和配置不同。** 函数签名是 4096 / 1.15，Qwen-Image 配置是 8192 / 0.9。算 mu 以配置为准。
6. **`shift_terminal 0.02` 没有出处。** 报告没提，只在配置里。源码注释说这段拉伸借自 LTX-Video（`scheduling_flow_match_euler_discrete.py:268` 附近的引用）。
7. **Qwen-Image-2.0 能查的数字不全。** 参数量、层数、预训练损失、CFG、scheduler、shift 都没写；也没有开源权重，没配置可查。网上流传的"7B"出自社区帖子，报告里没有。
8. **2.0 的"MMDiT"和 2.1 的"单流"说法对不上。** 2.0 报告写 MMDiT，但又说 "unified stream"、"shared transformer backbone"，是不是双流没写清；2.1 的 README 和 diffusers 源码明确是 32 层单流（`transformer_qwenimage21.py:584`、`:717`）。2.1 和 2.0 的 VAE（f16c64）、文字编码器（Qwen3-VL）对得上，但 2.1 没有自己的技术报告，不能直接说"2.1 = 开源的 2.0"。
9. **SD3 的 α=3 相对哪个基准分辨率没明说。** 正文说"在 1024² 上用 α = 3.0"；Figure 6 图注说的是"512² 模型、√(m/n) = 3.0"。片中只讲"1024² 用 shift 3"。
10. **Qwen-Image-2.1 在 2048² 时的 mu 超出配置区间。** 16,384 个 token 大于 `max_image_seq_len` 8192，代码按直线外推，e^mu ≈ 3.72，没有截断。只是推断，2.1 不当示例模型的话可以不提。
11. **HF 原站本机解析不了。** 配置是从 hf-mirror.com 拿的，HF API 返回的 repo sha 已记在 §1.1 和 §1.4。要和原站逐字比对，换一台能访问 huggingface.co 的机器再查一次。
